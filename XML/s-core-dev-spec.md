## 1. 프로젝트 개요

### 1.1 시스템 명칭
**S-CORE** (Seoul Economic Daily Score / Smart Core)

### 1.2 목적
종이 신문(지면)에 게재된 기사의 양적·질적 가치를 자동 측정하여 객관적인 인사평가 데이터로 활용합니다.

### 1.3 핵심 철학
> **"Max-Auto, Min-Manual"**
- 자동화: 게재 면, 글자 수, 기사 위치 등 시스템이 알 수 있는 정보는 100% 자동 입력
- 수동화: 품질 평가(단독, 기획, S등급)만 부장이 체크박스로 입력

### 1.4 사용자 그룹 (AWS Cognito 기반)

| 역할 | 권한 | 주요 기능 |
|:---|:---|:---|
| **Admin** | 전체 관리 | 사용자 관리, 가중치 설정, 데이터 내보내기 |
| **Manager (부장)** | 부서 단위 | 품질 가점 체크, 소명 승인/반려, 점수 조정 |
| **Reporter (기자)** | 본인 조회 | 본인 기사·점수 조회(Read-only), 소명 요청 |

## 2. 점수 산출 공식

### 2.1 기본 공식

```
기사 점수 = (면 가중치 × 분량 가중치 × 기본 점수) + 품질 가점
```

| 변수 | 설명 | 기본값 |
|:---|:---|:---|
| 기본 점수 | 기사 1건당 기준 점수 | 10점 |
| 면 가중치 | 게재 면에 따른 곱셈 계수 | 0.30 ~ 1.00 |
| 분량 가중치 | 글자 수에 따른 곱셈 계수 | 0.55 ~ 1.00 |
| 품질 가점 | 부장 체크 시 추가 점수 | 0 ~ 10점 (상한) |

**최대 점수:** 20점  
**최저 점수:** 1.7점 (시나리오 2 기준)

---

### 2.2 면 가중치 테이블

> Config에서 수정 가능하도록 설계

| 게재 면 | 가중치 | 비고 |
|:---:|:---:|:---|
| 1면 | 1.00 | 신문의 얼굴, 최고 주목도 |
| 2~3면 | 0.85 | 주요 뉴스 연장면 |
| 4~5면 | 0.70 | 핵심 뉴스면 |
| 6~10면 | 0.55 | 주요 섹션면 |
| 11~20면 | 0.40 | 일반 뉴스면 |
| 21~28면 | 0.30 | 후면부 |
| 29~32면 | 0.30 | 최후면부 |

**구현 참고:**
```javascript
function getPageWeight(page) {
  if (page === 1) return 1.00;
  if (page <= 3) return 0.85;
  if (page <= 5) return 0.70;
  if (page <= 10) return 0.55;
  if (page <= 20) return 0.40;
  return 0.30;
}
```

---

### 2.3 분량 가중치 테이블

> Config에서 수정 가능하도록 설계

| 글자 수 | 등급 | 가중치 | 기사 유형 예시 |
|:---|:---:|:---:|:---|
| 2,000자 이상 | L | 1.00 | 심층 분석, 기획, 인터뷰 |
| 1,200 ~ 1,999자 | M | 0.70 | 일반 스트레이트 |
| 600 ~ 1,199자 | S | 0.55 | 짧은 리포트 |
| 600자 미만 | XS | 0.55 | 단신, 브리프 |

**구현 참고:**
```javascript
function getLengthWeight(charCount) {
  if (charCount >= 2000) return 1.00;
  if (charCount >= 1200) return 0.70;
  return 0.55;
}
```

### 2.4 품질 가점 테이블

> 부장이 체크박스로 입력, 중복 체크 허용

| 항목 | 필드명 | 가점 | 판정 주체 |
|:---|:---|---:|:---|
| 면톱 | `isTopArticle` | +2점 | 부장 체크 |
| 단독/특종 | `isExclusive` | +5점 | 부장 체크 |
| 기획 | `isFeature` | +5점 | 부장 체크 |
| S등급 | `isSGrade` | +3점 | 부장 체크 |

**중요 규칙:**
- 모든 항목 중복 체크 가능 (단독 + 기획 + S등급 동시 가능)
- **품질 가점 합계 상한: 10점**
- 상한 초과 시 10점으로 제한

**구현 참고:**
```javascript
function calculateQualityBonus(article) {
  let bonus = 0;
  if (article.isTopArticle) bonus += 2;
  if (article.isExclusive) bonus += 5;
  if (article.isFeature) bonus += 5;
  if (article.isSGrade) bonus += 3;
  
  return Math.min(bonus, 10); // 상한 10점
}
```

---

### 2.5 최종 점수 계산 함수

```javascript
function calculateArticleScore(article) {
  const BASE_SCORE = 10;
  
  const pageWeight = getPageWeight(article.page);
  const lengthWeight = getLengthWeight(article.charCount);
  const qualityBonus = calculateQualityBonus(article);
  
  const baseScore = pageWeight * lengthWeight * BASE_SCORE;
  const finalScore = baseScore + qualityBonus;
  
  return Math.round(finalScore * 10) / 10; // 소수점 첫째 자리
}
```

## 4. 데이터 모델

### 4.1 기사 테이블 (Articles)

```typescript
interface Article {
  // 기본 정보 (편집 시스템에서 자동 수집)
  id: string;                    // 기사 고유 ID
  title: string;                 // 기사 제목
  reporterId: string;            // 작성 기자 ID
  reporterName: string;          // 작성 기자 이름
  departmentId: string;          // 부서 ID
  publishDate: string;           // 게재일 (YYYY-MM-DD)
  page: number;                  // 게재 면 (1~32)
  charCount: number;             // 글자 수
  
  // 품질 평가 (부장 입력)
  isTopArticle: boolean;         // 면톱 여부
  isExclusive: boolean;          // 단독/특종 여부
  isFeature: boolean;            // 기획 여부
  isSGrade: boolean;             // S등급 여부
  
  // 점수 (시스템 자동 계산)
  baseScore: number;             // 기본 점수 (면×분량×10)
  qualityBonus: number;          // 품질 가점
  totalScore: number;            // 최종 점수
  
  // 상태 관리
  status: 'PENDING' | 'CONFIRMED'; // 평가 상태
  confirmedAt?: string;          // 확정 일시
  confirmedBy?: string;          // 확정자 ID
  
  // 타임스탬프
  createdAt: string;
  updatedAt: string;
}
```

### 4.2 소명 테이블 (Appeals)

```typescript
interface Appeal {
  id: string;                    // 소명 ID
  
  // 요청자 정보
  reporterId: string;            // 기자 ID
  reporterName: string;          // 기자 이름
  departmentId: string;          // 부서 ID
  
  // 대상 기사
  articleId: string;             // 기사 ID
  articleTitle: string;          // 기사 제목 (스냅샷)
  
  // 소명 내용
  appealType: 'QUALITY_APPEAL' | 'SCORE_APPEAL' | 'MISSING_ARTICLE';
  qualityType?: 'EXCLUSIVE' | 'FEATURE' | 'S_GRADE' | 'TOP_ARTICLE';
  reason: string;                // 소명 사유 (최대 500자)
  
  // 상태
  status: 'SUBMITTED' | 'REVIEWING' | 'APPROVED' | 'REJECTED';
  
  // 처리 정보
  managerId?: string;            // 처리 부장 ID
  managerComment?: string;       // 부장 코멘트
  
  // 타임스탬프
  createdAt: string;
  submittedAt: string;
  reviewedAt?: string;
}
```

### 4.3 가중치 설정 테이블 (ScoreConfig)

```typescript
interface ScoreConfig {
  id: string;
  configType: 'PAGE_WEIGHT' | 'LENGTH_WEIGHT' | 'QUALITY_BONUS' | 'BASE_SCORE';
  
  // PAGE_WEIGHT인 경우
  pageRange?: { min: number; max: number };
  
  // LENGTH_WEIGHT인 경우
  charRange?: { min: number; max: number };
  
  // 값
  value: number;
  
  // 관리
  updatedAt: string;
  updatedBy: string;
  changeReason?: string;
}
```

## 7. 비즈니스 규칙

### 7.1 점수 관련

| 규칙 | 내용 |
|:---|:---|
| 품질 가점 상한 | 10점 (초과 시 10점으로 제한) |
| 최대 점수 | 20점 |
| 소수점 처리 | 첫째 자리까지 표시 (둘째 자리 반올림) |
| 점수 재계산 | 품질 가점 변경 시 즉시 재계산 |

### 7.2 소명 관련

| 규칙 | 내용 |
|:---|:---|
| 소명 기한 | 해당 월 마감일 + 5영업일 |
| 재소명 | 반려 후 1회에 한해 가능 |
| 처리 기한 | 제출 후 5영업일 이내 권고 |
| 미처리 시 | 월말 마감 시 자동 반려 |

### 7.3 확정 관련

| 규칙 | 내용 |
|:---|:---|
| 개별 확정 | 부장이 기사별로 확정 가능 |
| 일괄 확정 | 미확정 기사 전체를 현재 점수로 확정 |
| 확정 후 수정 | Admin만 가능 (사유 입력 필수) |

### 7.4 예외 가점

| 규칙 | 내용 |
|:---|:---|
| 대상 | 역대급 특종 (몇 년에 한 번 수준) |
| 권한 | Admin (편집국장/대표이사 승인) |
| 처리 | 수동 가점 부여, 20점 상한 무시 가능 |
| 기록 | 사유 입력 필수, 이력 로그 저장 |

## 8. 점수 공개 정책

### 8.1 Feature Flag 설정

```typescript
interface FeatureFlags {
  SHOW_MY_SCORE: boolean;           // 본인 점수 표시 (기본: true)
  SHOW_PREVIOUS_MONTH: boolean;     // 전월 대비 표시 (기본: true)
  SHOW_DEPT_AVERAGE: boolean;       // 부서 평균 표시 (기본: false)
  SHOW_DEPT_RANKING: boolean;       // 부서 내 순위 표시 (기본: false)
}
```

### 8.2 단계별 오픈

| 단계 | 공개 범위 | Flag 설정 |
|:---|:---|:---|
| **Phase 1** | 본인 점수 + 전월 대비 | `SHOW_DEPT_AVERAGE: false` |
| **Phase 2** | Phase 1 + 부서 평균 | `SHOW_DEPT_AVERAGE: true` |

**전환 조건:** 대표이사·편집국장 승인 시 Config 변경

## 9. 부서 가중치 안내

S-CORE는 Raw Score만 계산합니다. 부서 가중치는 인사팀 최종 환산 시 적용됩니다.

| 부서 구분 | 가중치 | 해당 부서 예시 |
|:---|:---:|:---|
| 가군 | 1.0 | 정치부, 경제부, 산업부, 금융부, 사회부 |
| 나군 | 1.1 | 문화부, 생활부, 스포츠부, 편집부 |

**기자 화면 표시 문구:**
> *"※ 나군 부서는 최종 평가 시 ×1.1 적용"*

## 10. 가중치 변경 관리

### 10.1 변경 권한
- 승인자: 대표이사, 편집국장
- 실행자: Admin

### 10.2 변경 이력 로그

```typescript
interface WeightChangeLog {
  id: string;
  changedAt: string;           // 변경 일시
  changedBy: string;           // 변경자 ID
  configType: string;          // 변경 항목
  previousValue: number;       // 이전 값
  newValue: number;            // 새 값
  reason: string;              // 변경 사유
  approvedBy?: string;         // 승인자 (대표/편집국장)
}
```

### 10.3 소급 적용
- 가능한 경우: 해당 월 점수 재계산
- 불가능한 경우: 익월부터 적용
